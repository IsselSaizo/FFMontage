## Обновление с 0.3.0 (M)

0.3.0 находит релиз через `releases/latest`, сравнивает версии (0.4.7 > 0.3.0), берёт архив с `win`/`linux` в имени
(новые имена подходят), подпись не проверяет; распаковка, замена exe и перезапуск совместимы с 0.4.7. Открытый ключ
в `update.rs` совпадает с ключом подписи. Настройки, режим portable, автосохранение и проекты 0.3 переносятся.

| ID | Пр. | Суть | Статус |
|---|---|---|---|
| M-1 | P1 | Переход с архива Linux на AppImage — другая папка настроек, первый запуск заново | ✅ в CHANGELOG и описании релиза |
| M-2 | P2 | Первый запуск срезал старый кэш (прокси, реверсы) до лимита 1 ГБ — пересчёт часами | ✅ без `meta.json` автоочистка пропускается один раз |
| M-3 | P2 | Обновление из 0.3.0 во время работы FFmpeg не заменит занятый `ffmpeg.exe` | ✅ совет в CHANGELOG |
| M-4…M-6 | P2 | Откат на 0.3.0 теряет настройки окна; вопрос о языке при первом запуске; проекты dev-сборок 0.5.x | приемлемо |

Риски выпуска: новый `release.yml` (подпись, AppImage) ещё ни разу не запускался; наличие секрета `FFM_SIGNING_KEY`
не проверено из репозитория; закреплённую сборку FFmpeg (BtbN autobuild-2026-11-04) стоит отзеркалить — BtbN
удаляет старые автосборки.
