# Аудит FF Montage 0.3.0 (29.10.2026)

Состояние после перехода с Electron на Tauri 2 (коммит `6399f99`). Аудит сделан только чтением кода. `cargo check` проходит без предупреждений.
Пути указаны от корня репозитория. Номера строк соответствуют коммиту `2f3d489`.
Задачи в [ROADMAP.md](ROADMAP.md) ссылаются на пункты аудита по идентификаторам (`B-1`, `R-3`…).

Не проверено вживую (нужна проверка на устройстве):
- кодеки HEVC, AV1 и MKV в WebView2, WebKitGTK и WKWebView;
- VAAPI на Steam Deck;
- импорт наших MXF в Avid и Resolve.

## 6. Фронтенд: архитектура и долги

- **Одна видеодорожка зашита везде.** Это плоский массив `project.videoClips` (`store.js`, 73 обращения в 9 файлах). На нём построены таймлайн, предпросмотр (`layersAt`), экспорт (линейный concat/xfade) и MCP.
- **Любое изменение вызывает одно событие `'project'`**, после чего полностью перерисовываются таймлайн (`innerHTML=''`), инспектор и медиатека. При перетаскивании это происходит на каждое движение мыши.
- **Undo хранит до 200 полных JSON-снимков** проекта со всеми эпизодами.
- **Хоткеи** обрабатываются одним `switch` в `app.js:220-269`. Подписи клавиш вручную продублированы в 5 местах. Реестра действий нет.
- **«Бог-объекты»:**
  - `store.js` — 1011 строк;
  - `timeline.js` — 917;
  - `mcpBridge.js` — 820 (с собственными копиями CODECS);
  - `app.js` — меню, хоткеи, обновления и сохранение в одном файле.
- **Настройки** — отдельное окно `setup.html` (только папки, после сохранения нужен перезапуск). Остальные настройки разбросаны по `localStorage` (`ffm.*`).
- **Меню:**
  - ☰ смешивает «Файл», «Настройки» и «Справку»;
  - сетка переходов есть и во вкладке, и в инспекторе;
  - блок «Действия» в инспекторе дублирует контекстное меню;
  - `S` означает и разрез, и соло в заголовке дорожки.
- **Под 1280×800 (Steam Deck) вёрстка не адаптирована:** медиазапросов нет, колонки 300+300 px, на плеер остаётся около 370 px. Hover и Alt на тачскрине не работают.
- **Прототипы реестров для плагинов:** `EFFECTS` (`effects.js:5`), `TRANSITIONS` (`transitions.js:16`) + `XFADE` (`exportPlan.js:53`), MCP `TOOLS` (`mcpBridge.js:303`).

## 7. Порты

- **Steam Deck / Linux:**
  - `config.json` и кэш лежат рядом с exe; в AppImage и Flatpak эта папка только для чтения (`paths.rs:46-65,88-93`) → нужны XDG-пути;
  - FFmpeg надо поставлять вместе с программой;
  - `<video>` играет через GStreamer, у AppImage для этого есть опция `bundleMediaFramework`;
  - для кодирования нужен VAAPI (`h264_vaapi`/`hevc_vaapi`; AV1 Deck не кодирует);
  - самообновление в AppImage должно заменять файл `$APPIMAGE`, во Flatpak его нужно выключить;
  - `setup.sh` рассчитан только на apt.
- **macOS:**
  - писать данные внутрь `.app` нельзя → `~/Library/Application Support` и `~/Library/Caches`;
  - FFmpeg — sidecar с подписью и нотаризацией;
  - `update.rs` выбирает Linux-ассет, сборки arm64 нет;
  - WKWebView не играет MKV/WebM, поэтому `BROWSER_CONTAINERS` должен зависеть от платформы;
  - VideoToolbox;
  - `selftest.rs` работает только с WebView2;
  - при `decorations(false)` пропадают кнопки-«светофор».
- **Android / iOS:**
  - нет lib-таргета и `mobile_entry_point`;
  - отдельный процесс ffmpeg запустить нельзя: на iOS вообще, на Android — только как `lib*.so` → нужен libav* через FFmpegKitNext или собственную сборку;
  - для App Store нужна LGPL-сборка;
  - файлы приходят как `content://`;
  - drag-drop и именованных каналов нет.

## 8. CI и релиз

- Нет jobs для macOS, aarch64, AppImage/Flatpak. Нет clippy, fmt и `cargo test`.
- FFmpeg берётся из BtbN `latest` без фиксации версии и SHA256.

## 9. Возможности нашей сборки FFmpeg (n9.0.1 BtbN win64-gpl)

Всё, что понадобится по плану, в сборке есть:
- amerge/pan/join/channelsplit;
- pcm_s24le, prores_ks, dnxhd, mpeg2video (XDCAM);
- контейнеры mov, mxf (OP1a), matroska;
- libass, freetype, harfbuzz, fontconfig (subtitles/ass/drawtext);
- overlay/xstack/rotate/crop/colorkey;
- `*_cuda`;
- loudnorm/ebur128/scdet/afftdn/rubberband/vidstab/lut3d/zscale/libplacebo;
- энкодеры nvenc/qsv/amf/vulkan.

Рецепты проверены на синтетике и записаны в ROADMAP (раздел «Справочник FFmpeg»). Подводные камни:
- **VP9 с альфой** открывать с `-c:v libvpx-vp9` перед `-i`, иначе альфа теряется.
- **Файл графа фильтров** писать без BOM.
- **Текст пользователя** передавать только через `textfile=` + `expansion=none`.
- **Пути в графе:** `\`→`/`, `:`→`\:`, всё в `'…'`.
- **XDCAM** в FFmpeg 9: вместо `-top` использовать `setfield=tff`.
- **`overlay_cuda`:**
  - нужен `setparams` с одинаковыми цветовыми метками у входов;
  - кадры из NVDEC приходят высотой 1088 — подавать через `hwupload_cuda`.
- **`fontsdir`** указывать только на папку шрифтов проекта, не на `C:/Windows/Fonts`.
