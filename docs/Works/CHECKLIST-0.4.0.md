# Что проверить руками перед выпуском 0.4.x (первый выпуск — 0.4.7)

Автотесты (engine-test, mcp-test, ui-selftest*, cargo test, i18n-check) проходят на Windows. Здесь только то,
что автоматикой не проверить: глазами, на другом железе или с ключами и аккаунтами. Отмечайте `[x]`, замечания пишите рядом.

Обозначения: 🖥 — нужна только эта машина; 🔑 — нужен доступ (GitHub, ключи); 🧰 — нужно другое железо или ОС.

## 1. Монтаж и плеер (M4)

- [ ] 🖥 Гизмо в плеере: двигать, масштаб за углы, поворот за кружок (Shift — шаг 15°), магнит к центру и краям — удобно ли, не «прыгает» ли.
- [ ] 🖥 Две-три видеодорожки одновременно при воспроизведении: нет рывков, звук не уходит, слои в правильном порядке.
- [ ] 🖥 Переходы на верхней дорожке в плеере выглядят так же, как в экспорте.
- [ ] 🖥 Пример-плагин «Раскладки кадра»: плитки панели, PiP и сетки.
- [ ] 🖥 Перетаскивание клипа мышью между видеодорожками (с Alt и без) — автотест иногда здесь спотыкается, проверьте вручную.

## 2. Текст и субтитры (M5)

- [ ] 🖥 Вкладка «Текст»: все 5 стилей ставятся, миниатюры читаемые.
- [ ] 🖥 Текст в плеере и в готовом файле совпадает (размер, перенос строк, обводка, тень, подложка, жирность).
- [ ] 🖥 Жирный и курсив Inter во **вшитых субтитрах**: libass у вариативного шрифта может рисовать жирный синтетически.
- [ ] 🖥 Размер субтитров в плеере и в файле (в плеере — приближение, допустимо 1–2 px).
- [ ] 🖥 Титры «снизу вверх» при воспроизведении — плавно, скорость как в файле.
- [ ] 🖥 Рамка гизмо у текста (особенно у повёрнутого и многострочного).
- [ ] 🖥 Свой шрифт: вкладка «Текст» → «Добавить шрифт…» (.ttf/.otf с кириллицей) → текст этим шрифтом в плеере и в экспорте, субтитры этим шрифтом (вшитые).
- [ ] 🖥 Импорт настоящих SRT/ASS из интернета (в т. ч. в Windows-1251 и с тегами ASS) и перетаскивание файла субтитров в окно.
- [ ] 🖥 Экспорт «Отдельной дорожкой»: в VLC / проигрывателе Windows субтитры включаются и выключаются, язык подписан.

## 3. Проекты (M6)

- [ ] 🖥 Открыть 3–5 настоящих проектов 0.3.x: всё на месте (клипы, переходы, «Наложения» стали верхней дорожкой), после сохранения рядом есть «Имя (0.3).ffproj», экспорт совпадает с тем, что было.
- [ ] 🖥 Проект, сохранённый 0.4, при открытии в 0.4 — без лишних предупреждений.

## 4. Экспорт и видеокарты (M0.2, M0.4, M0.9)

- [ ] 🖥 Окно экспорта: подпись «Видеокарта NVIDIA», кнопка «Проверить заново» (сбрасывает кэш проверки кодировщиков).
- [ ] 🖥 Экспорт в свою папку через «Выбрать…» и в папку по умолчанию — проходит (новая проверка разрешает только выданные пути).
- [ ] 🖥 ИИ-ассистент: `export_video` с `path` в папку вне кэша (например, на рабочий стол) — проходит.
- [ ] 🧰 Intel (встроенная или Arc): h264/hevc/av1_qsv — экспорт с качеством «высокое» и «компактное»; на старых iGPU av1_qsv нет, это нормально.
- [ ] 🧰 AMD: h264/hevc/av1_amf — экспорт и качество (у av1_amf шкала QP 0–255 подобрана без проверки).
- [ ] 🧰 Linux / Steam Deck: h264/hevc_vaapi (устройство `/dev/dri/renderD128` зашито) — экспорт проходит, картинка без артефактов.
- [ ] 🖥 Часовое видео: миниатюры, звуковая волна, реверс фрагмента не обрываются по таймауту (лимит 5 мин + 3× длительность).
- [ ] 🖥 Много клипов сразу (20+): программа не «задыхается» — фоновые задачи идут очередью (8 на процессоре, 3 на видеокарте).
- [ ] 🧰 Linux: второй запуск при зависшей первой копии — через ~3 с открывается новое окно, а не висит.

## 5. Где лежат данные, настройки, кэш (M0.5–M0.7)

- [ ] 🖥 Windows zip, распакованный в новую папку → portable: `config.json` и `settings.json` появляются рядом с exe.
- [ ] 🖥 Тот же exe в `C:\Program Files\FF Montage` (или папке только для чтения) → окно первого запуска предлагает кэш в
      `%LOCALAPPDATA%\FF Montage`, настройки пишутся в `%APPDATA%\FF Montage`.
- [ ] 🖥 Обновление вашей рабочей копии 0.3 → 0.4: язык и горячие клавиши на месте (переехали из `config.json` в `settings.json`);
      вкладка справа, высота таймлайна, магнит, громкость предпросмотра, настройки экспорта — тоже.
- [ ] 🖥 «Настройки → Папки» → блок «Где хранятся данные»: режим и папки показаны верно; смена режима по подсказке
      (`portable.txt` и перенос файлов) работает.
- [ ] 🖥 «Настройки → Кэш»: ползунок 1–50 ГБ (по умолчанию 1), «Сейчас занято». На большом настоящем кэше уменьшить лимит —
      старое удаляется, а прокси и реверсы открытого проекта остаются.
- [ ] 🖥 «Очистить» во время экспорта → отказ с понятным сообщением.
- [ ] 🖥 Перенести папку кэша («Папки») → миниатюры старых медиа открываются (B-9).
- [ ] 🧰 Linux: пути XDG (`~/.config/ff-montage`, `~/.cache/ff-montage`, `~/.local/share/ff-montage`), в том числе с заданными `XDG_*_HOME`.

## 6. Выпуск и обновления (M0.10, M0.12)

- [ ] 🔑 GitHub → Settings → Secrets and variables → Actions: секрет `FFM_SIGNING_KEY` = всё содержимое
      `F:\FFmpeg\FFMontage-keys\update-signing.key` (вместе со строками BEGIN/END), или
      `gh secret set FFM_SIGNING_KEY < F:\FFmpeg\FFMontage-keys\update-signing.key`.
- [ ] 🔑 Резервная копия папки `F:\FFmpeg\FFMontage-keys` офлайн (флешка, менеджер паролей). Без этого ключа версии 0.4+ не примут ни одного обновления.
- [ ] 🔑 Тег `v0.4.7` → в Actions зелёные jobs `version` и `publish`, в релизе лежат `SHA256SUMS`, `SHA256SUMS.sig`,
      `FF-Montage-0.4.7-windows-x64.zip`, `…-linux-x86_64.AppImage`, `…-linux-x86_64.tar.gz`. Локально: `node tools/sign-release.mjs verify <папка с ассетами>`.
- [ ] 🖥 Обновление 0.3.0 → 0.4.7 (идёт старым кодом, без подписи): «Проверить обновления» в 0.3.0 находит zip, ставит, программа перезапускается, настройки и проекты на месте.
- [ ] 🔑 Позже, при 0.4.8: обновление из 0.4.7 проверяет подпись и ставится; релиз без `.sig` → «обновление не установлено».
- [ ] 🔑 Зеркалировать архивы FFmpeg BtbN (`autobuild-2026-11-04-12-51`, win64 и linux64) в свой релиз, например с тегом `ffmpeg-9.0.2`, и поменять URL в `tools/fetch-ffmpeg.*`: BtbN со временем удаляет старые сборки, тогда CI упадёт с 404.
- [ ] 🖥 Сверить пресеты горячих клавиш Resolve / Premiere / CapCut ([HOTKEYS.md](../Guides/HOTKEYS.md)) в самих программах.

## 7. Linux и Steam Deck (0.4.2)

Уже проверяет CI на каждый push в main (workflow «AppImage», без видеокарты, под xvfb): AppImage собирается
(`bundleMediaFramework`, FFmpeg BtbN по SHA-256 в `usr/bin/ffmpeg/bin`), внутри есть ffmpeg/ffprobe с `h264_vaapi`/`hevc_vaapi`
и нужные плагины GStreamer (autodetect, playback, isomp4, matroska, libav, pulseaudio…), движок из образа берёт FFmpeg
из образа (подставной `ffmpeg` в `PATH` игнорируется), режим путей — system (XDG), программа видит свой `$APPIMAGE`,
обновление выберет ассет `…-linux-x86_64.AppImage`; окно открывается и играет `<video>` H.264/VP9 напрямую, HEVC — через прокси.
AppImage входит в каждый релиз (выключить — переменная репозитория `FFM_APPIMAGE=0`).

Руками, на живом Steam Deck (и на одном обычном Linux, например Ubuntu 24.04 или Fedora):

- [ ] 🎮 `chmod +x`, запуск двойным щелчком в режиме рабочего стола; окно первого запуска, папки на SD-карте.
- [ ] 🎮 Видео и **звук** в плеере (GStreamer из образа → PulseAudio/PipeWire Deck), перемотка, несколько дорожек.
      Если окно белое/пустое — попробовать `WEBKIT_DISABLE_DMABUF_RENDERER=1 ./FF-Montage-….AppImage` и записать результат.
- [ ] 🎮 Импорт записи с Deck (H.264) и HEVC-файла: HEVC уходит в прокси и играет.
- [ ] 🎮 Экспорт: `h264_vaapi` / `hevc_vaapi` видны в списке кодировщиков и работают (AV1 — процессор).
- [ ] 🎮 `./FF-Montage-….AppImage --engine info </dev/null`: `ffmpeg.bundled: true`, `gst.missing: []`, `paths.mode: system`.
- [ ] 🎮 Добавить как «стороннюю игру» в Steam, запуск из игрового режима: окно на весь экран, экранная клавиатура (Steam + X).
- [ ] 🎮 Обновление: поставить AppImage прошлой версии → «Проверить обновления…» → файл подменился (то же имя), программа
      перезапустилась новой версией, ярлык Steam работает.
- [ ] 🎮 ИИ-ассистент: в настройках MCP-клиента путь — к самому `.AppImage`, а не к `/tmp/.mount_…`.
- [ ] 🎮 Тач и геймпад (gamepad.js, крупные ручки при `pointer: coarse`): сенсорный экран Deck и кнопки/стики в окне.
