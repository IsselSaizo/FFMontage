# Плагины FF Montage (API v1)

Плагин — папка с файлом `plugin.json` и, по желанию, скриптами и страницами. Через плагины в программу
добавляются эффекты, переходы, звуковые эффекты, пресеты экспорта и горячих клавиш, действия и панели.
Встроенные эффекты и переходы устроены так же: это плагин `core`, он пользуется тем же API.

Готовые примеры: встроенные [`plugins-bundled/vignette`](../../plugins-bundled/vignette) и
[`plugins-bundled/restore`](../../plugins-bundled/restore), [`plugins-bundled/stabilize`](../../plugins-bundled/stabilize) (эффекты без единой строки кода),
[`examples/plugins/project-stats`](../../examples/plugins/project-stats) (панель, действие с клавишей, хранилище),
[`examples/plugins/layouts`](../../examples/plugins/layouts) (раскладки кадра: картинка в картинке и сетки через `set_transform`).

## Встроенные плагины

Вместе с программой поставляются плагины из папки [`plugins-bundled`](../../plugins-bundled) репозитория —
«Виньетка» (`vignette`), «Восстановление записи» (`restore`: шумодав для старых и сжатых записей) и
«Стабилизация» (`stabilize`: быстрая, баланс, максимум). Их файлы
встроены в exe; при запуске программа копирует недостающие в `plugins/<id>/`, а если там версия старее
встроенной (`version`, сравнение по semver) — обновляет. Ту же или более новую версию не трогает.

Встроенный плагин выключают и удаляют как обычный (в списке он помечен «встроенный»). Удалённый запоминается
(`settings.json` → `plugins.removedBundled`) и при запуске и обновлении программы не возвращается; кнопка
«Вернуть встроенные» в «Настройки → Плагины» ставит удалённые снова. Если установить вручную плагин с тем же id,
он перестаёт считаться удалённым (и при следующем обновлении программы заменится, если встроенная версия новее).

Чтобы добавить встроенный плагин: папка `plugins-bundled/<id>/` с `plugin.json` (и, если нужно, другими файлами —
build.rs встраивает всю папку, кроме скрытых файлов); проверки — `cargo test` (`bundled::tests`) и
`node tests/bundled-test.js` (манифесты, графы и прогон через FFmpeg).

## Установка

**☰ → Настройки → Плагины**: «Из папки…», «Из zip…» или «С GitHub…» (`владелец/репозиторий` — берётся
`.zip` из последнего релиза; если рядом лежит `<имя>.zip.sha256` или `SHA256SUMS`, контрольная сумма проверяется).
Перед установкой программа показывает, какие права просит плагин. Там же плагин выключают, обновляют (повторная
установка заменяет старую версию) и удаляют.

Плагины лежат в папке `plugins/<id>/` рядом с программой (её открывает кнопка «Открыть папку»).
Если плагин пропал, проект всё равно открывается: программа предупреждает, какие эффекты не найдены, а сами
настройки клипов сохраняются — после установки плагина всё вернётся.

## Безопасность

- Код плагина работает в песочнице: `<iframe sandbox="allow-scripts">` без общего происхождения с программой.
  У него нет доступа к окну программы, к файлам, к FFmpeg и к командам программы — только к `window.ffm`.
- Сеть закрыта (CSP `connect-src` — только файлы самого плагина). Запросы в интернет — через `ffm.net.fetch`
  и только к хостам, перечисленным в правах `net:<хост>` (только https).
- FFmpeg плагин не запускает. Эффект описывает фрагмент графа фильтров декларативно; программа подставляет
  числа, проверяет имена фильтров и опций, а Rust перед запуском ещё раз проверяет весь граф и аргументы.
  Разрешены только фильтры из [`safeFilters.js`](../../src/renderer/js/core/safeFilters.js), которые плагин
  перечислил в `ffmpeg.filters`. Фильтры, читающие файлы или сеть (`movie`, `subtitles`, `lut3d`, `sendcmd` …),
  и опции вроде `file`/`filename` запрещены.

## plugin.json

```json
{
  "id": "my-plugin",
  "name": { "ru": "Мой плагин", "en": "My plugin" },
  "version": "1.0.0",
  "apiVersion": 1,
  "description": { "ru": "…", "en": "…" },
  "author": "Имя",
  "homepage": "https://github.com/…",
  "entry": "main.js",
  "contributes": {
    "effects": [], "transitions": [], "audioEffects": [], "exportPresets": [], "textStyles": [], "loudnessTargets": [],
    "keymaps": [], "actions": [], "panels": [], "library": []
  },
  "permissions": ["project:read", "storage"],
  "ffmpeg": { "filters": ["vignette"] }
}
```

| Поле | |
|---|---|
| `id` | латиница в нижнем регистре, цифры и `-`, 2–41 символ; не `core`. Эффекты плагина получают id `<id плагина>.<id эффекта>` |
| `name`, `description` | строка или `{ "ru": …, "en": … }` (так же — все подписи ниже) |
| `apiVersion` | `1` |
| `minAppVersion` | необязательно (0.6.1): самая старая версия FF Montage, в которой плагин работает |
| `entry` | необязательный ES-модуль логики; выполняется в скрытой песочнице всё время, пока плагин включён |
| `contributes` | что плагин добавляет (см. ниже). Всё из `contributes` регистрируется само, без кода |
| `permissions` | права (см. таблицу) |
| `ffmpeg.filters` | фильтры FFmpeg, которые используют эффекты плагина |

### Права

| Право | Что даёт |
|---|---|
| `project:read` | `ffm.project.get/subscribe`, `ffm.tools.call('get_project')` |
| `project:write` | (включает `project:read`) `ffm.commands.execute`, изменяющие инструменты `ffm.tools.call` — с отменой Ctrl+Z |
| `ui:panel` | панели в правой части окна (без этого права `contributes.panels` не показываются) |
| `storage` | `ffm.storage` — свой JSON до 1 МБ |
| `notify` | не обязательно: `ffm.ui.notify` доступен всем (не больше 5 сообщений за 10 с) |
| `net:<хост>` | `ffm.net.fetch` к `https://<хост>/…` |

Инструменты для `ffm.tools.call`: `get_project`, `add_clip`, `update_clip`, `split_clip`, `delete_clip`,
`reverse_clip`, `freeze_frame`, `set_transition`, `close_gaps`, `add_video_track`, `update_video_track`, `set_transform`,
`add_text`, `update_text`, `set_subtitles` (без `path`), `update_subtitles`, `set_audio_layout`, `route_track`, `split_channels`, `undo`, `redo`, `set_playhead` (аргументы — как
у ИИ-ассистента, см. описание MCP). Файловые инструменты и экспорт плагинам недоступны. `ffm.commands.execute`
не выполняет действия меню «Файл» и действия других плагинов.

Только что установленный плагин выключен: программа показывает его права и включает его по вашему согласию.

## Выражения в описаниях

В строках описаний можно писать выражения в фигурных скобках: `{strength * 0.75}` или `{strength * 0.75:3}`
(после двоеточия — число знаков после запятой; по умолчанию 6). Доступны параметры эффекта, `w` (ширина кадра:
исходного — для FFmpeg, показанного в плеере — для CSS), `p` (доля перехода 0…1), операции `+ - * / %`,
сравнения `< > <= >= == != && || !` и функции `min max clamp abs round floor ceil pow sqrt db` (`db(x)` = 10^(x/20)).

## Эффект (видео)

```json
{
  "id": "vignette",
  "name": { "ru": "Виньетка", "en": "Vignette" },
  "params": [ { "k": "strength", "name": "Сила", "min": 0, "max": 1, "step": 0.05, "def": 0.5 } ],
  "ffmpeg": [ { "filter": "vignette", "args": { "angle": "{0.15 + strength * 0.75:4}" }, "when": "strength > 0" } ],
  "css": "brightness({1 - strength * 0.12:3})"
}
```
- `ffmpeg` — цепочка фильтров, которая ставится на клип до масштабирования. `args` — объект `{опция: значение}`
  или массив позиционных значений. `when` — фильтр ставится, только если выражение истинно.
- `css` — CSS `filter` для предпросмотра в плеере (приближение; что не выразить CSS — просто не показывается).
- `"preview"` — как эффект видно в плеере (по умолчанию — через `css`):
  - `"frame"` — CSS-превью нет или оно условное (шумодав, виньетка): в инспекторе пометка «видно только в экспорте»
    и кнопка «Сравнить» — шторка ДО/ПОСЛЕ в плеере. Оба кадра делает FFmpeg из исходного файла в один проход:
    ДО — без эффектов, ПОСЛЕ — вся цепочка эффектов клипа (та же, что в экспорте), с одинаковым кадрированием и
    масштабом. Временны́е фильтры (`hqdn3d`, `atadenoise`) прогоняются с ~0,5 с до момента. Разрез вертикальный или
    горизонтальный, границу тянут мышью; кадры пересчитываются после остановки (~0,3 с) и кэшируются.
  - `"proxy"` — эффект меняет движение, а не кадр (стабилизация): шторки нет, в инспекторе чекбокс
    «Показывать превью» (по умолчанию выключен — пометка «видно только в экспорте»). Включён — программа в фоне
    делает копию отрезка клипа с эффектом в низком разрешении (~720p) и плеер играет её вместо исходника; остальные
    эффекты клипа плеер по-прежнему накладывает через CSS. Только вместе с `"stage": "source"`. Значение чекбокса
    хранится в проекте: `clip.fxp["<плагин>.<эффект>"].showPreview`.
- `"stage": "source"` — эффект работает с кадрами самого файла и ставится **первым** в цепочке клипа: до скорости,
  кадрирования, трансформа и остальных эффектов (стабилизация). У клипа действует только один такой эффект:
  включение другого заменяет прежний.
- `"prepare"` — шаг подготовки клипа, который делает **программа** (см. ниже «Подготовка клипа»).
- Значения после подстановки не могут содержать `' " \ ; [ ] ,` и перевод строки.
- Опции с именем не из латинской буквы (у `atadenoise` — `0a`, `0b`, …) задавайте позиционно, массивом `args`
  (см. `plugins-bundled/restore`). Помните о значениях «0 = по умолчанию»: например, `hqdn3d` с `luma_spatial=0`
  берёт 4, поэтому выключенную ступень лучше убирать через `when`, а минимум задавать как `max(x, 0.01)`.

### «Восстановление записи» (`restore`)

| Эффект | Цепочка | Ползунки (по умолчанию) |
|---|---|---|
| «Шумодав» (`restore.denoise`) | `deblock` (filter=strong) → `hqdn3d` → `atadenoise` → `unsharp` | Квадраты сжатия 0–10 (5), Размер квадрата 4–32 (8), Шум в кадре 0–10 (4), Шум между кадрами 0–30 (6), Усреднение кадров 0–10 (2), Резкость 0–2 (0) |
| «Шумодав (качественно, медленно)» (`restore.denoise-hq`) | `deblock` → `nlmeans` (p=7, r=15) → `unsharp` | Квадраты сжатия (5), Размер квадрата (8), Сила 0–15 (3), Резкость (0) |

Ползунок на 0 выключает свою ступень. По умолчанию `hqdn3d` мягкий (4:3:6:4); сильная временна́я составляющая
(20–30) даёт шлейфы на движении. `nlmeans` заметно медленнее (на 1080p — порядка кадра в секунду).

### Подготовка клипа (`prepare`) и плейсхолдер файла

Некоторым фильтрам нужен файл, который считается заранее по всему клипу: `vidstabtransform` (стабилизация vidstab)
читает результат анализа движения `vidstabdetect`. Плагин такой файл задать не может — он объявляет подготовку,
а программа делает её сама:

```json
{
  "id": "balanced", "name": "Стабилизация", "stage": "source", "preview": "proxy",
  "prepare": { "kind": "vidstab", "args": { "shakiness": "{shake:0}", "accuracy": "9", "stepsize": "12", "mincontrast": "0.3", "tripod": "{tripod:0}" } },
  "params": [ { "k": "shake", "name": "Тряска", "min": 1, "max": 10, "step": 1, "def": 5 }, … ],
  "ffmpeg": [ { "filter": "vidstabtransform", "args": { "input": "{trf}", "smoothing": "{smooth:0}", "optzoom": "1" } } ]
}
```

- `prepare.kind` — пока только `vidstab`; `args` — шаблоны от параметров эффекта для `shakiness` (1–10), `accuracy`
  (1–15), `stepsize` (1–32), `mincontrast` (0–1), `tripod` (0/1). Эффекту с `prepare` нужен `"stage": "source"`.
- Фильтры хоста (`HOST_FILTERS` в `safeFilters.js`, сейчас только `vidstabtransform`) разрешены только эффекту с
  подходящим `prepare` и объявляются в `ffmpeg.filters` как обычные. Опция с файлом (`input`) пишется ровно как
  плейсхолдер **`"{trf}"`** — путь подставляет программа. `vidstabdetect` (он пишет файл) плагинам не дан никогда.
- Анализ запускает программа в фоне, как только эффект включён, изменились параметры анализа или клип обрезан за
  пределы запаса: `vidstabdetect` по отрезку файла клипа с запасом ~1 с по краям → `<кэш>/app/media/<ключ файла>/stab/<хэш>.trf`
  (кэш по файлу, отрезку и параметрам анализа; категория «Стабилизация» в «Настройки → Кэш»). Статус — в инспекторе
  («Анализ движения… 43%», «готово», ошибка с кнопкой «Повторить»). Не готов к экспорту — экспорт сначала доделывает
  его («Подготовка: анализ движения…»), «Отмена» отменяет и анализ.
- `.trf` привязан к номерам кадров: экспорт подаёт FFmpeg ровно тот же отрезок (`-ss`/`-t`), что анализировался,
  после `vidstabtransform` срезает запас (`trim`) — кадры стабилизированного клипа совпадают по времени с исходными.
- Rust (`plancheck.rs`) пропускает `vidstabtransform` только с `input=` — существующим `.trf` внутри папки `stab`
  кэша медиа, без `..`, с опциями из списка (`smoothing`, `optzoom`, `zoom`, `interpol`, `tripod`, `crop`, …; не `debug`).
- Нет vidstab в сборке FFmpeg (`ffmpeg -filters`) — такие эффекты недоступны (подсказка в списке фильтров и
  инспекторе), экспорт пропускает их с предупреждением.

### «Стабилизация» (`stabilize`)

| Эффект | Как работает | Ползунки (по умолчанию) |
|---|---|---|
| «Стабилизация: быстрая» (`stabilize.fast`) | `deshake` (один проход, любая сборка FFmpeg) → зум `scale`+`crop`, чтобы спрятать края | Размах тряски 16–64 пикс. (32, rx/ry), Зум 0–20 % (4) |
| «Стабилизация: баланс» (`stabilize.balanced`) | анализ `shakiness={shake}:accuracy=9:stepsize=12:mincontrast=0.3` → `vidstabtransform` (bilinear, `optzoom=1`) | Сглаживание 1–60 кадров (15), Доп. зум 0–20 % (0), Сила тряски 1–10 (5), Штатив 0/1 (0) |
| «Стабилизация: максимум» (`stabilize.max`) | анализ `shakiness=10:accuracy=15:stepsize=6:mincontrast=0.1` → `vidstabtransform` (bicubic, `optzoom=1`) → `unsharp` | Сглаживание 1–100 (30), Доп. зум (0), Резкость 0–1,5 (0,5), Штатив (0) |

«Баланс» и «Максимум» нужна GPL-сборка FFmpeg с vidstab. `optzoom=1` подбирает постоянный зум, при котором не видно
чёрных плавающих краёв. «Штатив» — камера должна стоять на месте (опорный кадр — первый кадр отрезка анализа).

## Переход

```json
{
  "id": "split",
  "name": "Раскрытие",
  "xfade": "vertopen",
  "preview": { "b": { "clipPath": "inset(0 {(1 - p) * 50}% 0 {(1 - p) * 50}%)" } }
}
```
- `xfade` — имя встроенного перехода фильтра `xfade` или `{ "expr": "…" }` — своё выражение xfade
  (переменные `A`, `B`, `X`, `Y`, `W`, `H`, `P`; `P` идёт от 1 к 0). Пример — встроенные «Жалюзи».
- `preview` — стили двух слоёв в плеере: `a` — уходящий клип, `b` — следующий; поля `opacity`, `transform`,
  `clipPath`, `mask`, `filter`; `top: "a"` — уходящий слой сверху; `overlay: { color, opacity }` — заливка поверх.

## Звуковой эффект

```json
{
  "id": "telephone",
  "name": "Телефон",
  "params": [ { "k": "tone", "name": "Тон", "min": 500, "max": 3000, "step": 50, "def": 1500, "unit": "Гц" } ],
  "ffmpeg": [ { "filter": "bandpass", "args": { "f": "{tone:0}", "width_type": "q", "w": "1.2" } } ],
  "webaudio": [ { "node": "biquad", "type": "bandpass", "frequency": "{tone}", "Q": "1.2" } ]
}
```
- `webaudio` — как эффект звучит в предпросмотре: узлы `biquad` (`type`, `frequency`, `gain`, `Q`),
  `compressor` (`threshold`, `ratio`, `attack`, `release`, `knee`), `gain` (`gain`). Без `webaudio`
  эффект слышно только в готовом файле (как шумоподавление).

## Стиль текста

```json
"textStyles": [ {
  "id": "neon", "name": { "ru": "Неон", "en": "Neon" }, "kind": "title", "duration": 4,
  "text": { "content": "NEON", "font": "Inter", "size": 0.12, "weight": 800, "color": "#ff4dff",
            "strokeWidth": 0.04, "strokeColor": "#2a003a", "shadowOpacity": 0.8, "shadowColor": "#ff00ff", "shadowBlur": 0.3 },
  "transform": { "y": -0.2 }
} ]
```
- Стиль появляется плиткой во вкладке «Текст»; щелчок ставит текстовый клип с этим оформлением.
- `kind` — `title`, `lower`, `caption`, `credits` или `other`; `duration` — 0,5…600 с; `transform` — как у `set_transform`.
- Поля `text`: `content`, `font` (имя шрифта: встроенные `Inter`, `Open Sans` или свой шрифт пользователя — если его нет, будет запасной), `size` (высота шрифта в долях высоты кадра), `weight`, `italic`, `color`, `align` (`left`/`center`/`right`), `lineHeight`, `letterSpacing` (em), `wrap` (ширина строки в долях кадра, 0 — без переноса), `strokeWidth`/`strokeColor` (обводка в долях размера шрифта), `shadowOpacity`/`shadowColor`/`shadowBlur`/`shadowX`/`shadowY`, `box`/`boxColor`/`boxOpacity`/`boxPad`/`boxRadius` (подложка), `motion` (`none` или `roll` — титры снизу вверх). Неизвестные поля — ошибка регистрации.
- Текст рисует сама программа (один и тот же код для плеера и для экспорта), поэтому плагин задаёт только оформление.

## Цель громкости (0.5.0)

```json
"loudnessTargets": [ { "id": "atsc", "name": { "ru": "США: −24 LUFS (ATSC A/85)", "en": "US: −24 LUFS (ATSC A/85)" }, "i": -24, "tp": -2, "lra": 11, "hint": "…" } ]
```
- Цель появляется в списке «Громкость» окна экспорта и в MCP `export_video loudness` (id — `<плагин>.<id>`).
- `i` — целевая громкость, −70…−5 LUFS; `tp` — предел истинного пика, −9…0 dBTP (по умолчанию −1);
  `lra` — диапазон громкости, 1…20 LU (по умолчанию 11); `hint` — подсказка под списком.
- Экспорт идёт в два прохода (замер `loudnorm`, затем запись по замеру) — плагин задаёт только числа.
- Из логики плагина: `ffm.register.loudnessTarget({ id, name, i, tp, lra })`.

## Библиотека: звуки и картинки (0.6.1)

Плагин может положить в вкладку **«Библиотека»** (левая панель) свои звуки и картинки — без кода и без прав.
Пример — плагин [«Реакции зала»](https://github.com/IsselSaizo/ffmontage-reactions) (мемы-реакции и звуки зала).

```json
"minAppVersion": "0.6.1",
"contributes": {
  "library": [
    { "id": "ovation", "kind": "audio", "file": "sounds/ovation.ogg",
      "name": { "ru": "Овации", "en": "Ovation" }, "group": { "ru": "Звуки зала", "en": "Crowd sounds" }, "volume": 1 },
    { "id": "facepalm", "kind": "image", "file": "memes/facepalm.jpg", "duration": 3,
      "name": { "ru": "Фейспалм", "en": "Facepalm" }, "group": { "ru": "Мемы-реакции", "en": "Reaction memes" },
      "sticker": { "corner": "bottom-right", "size": 0.45, "margin": 0.04 },
      "border": { "width": 0.0025, "color": "#ffffff", "radius": 0.018 } }
  ]
}
```

| Поле | |
|---|---|
| `kind` | `audio` (wav, mp3, ogg, opus, m4a, flac) или `image` (png, jpg, webp, gif) |
| `file` | путь внутри папки плагина; файл проверяется при установке |
| `group` | заголовок раздела в «Библиотеке» (без него — имя плагина) |
| `volume` | звук: громкость клипа 0…2 |
| `duration` | картинка: длина клипа, 0,5…600 с (по умолчанию 3) |
| `sticker` | картинка: наклейкой — `corner` (`bottom-right`, `bottom-left`, `top-right`, `top-left`, `center`), `size` — ширина в долях меньшей стороны кадра (0,05…1), `margin` — отступ от краёв в тех же долях. Без `sticker` — во весь кадр |
| `border` | картинка: обводка и скругление углов, как у клипа (`width`, `color`, `radius` — доли высоты кадра) |

- Щелчок по плитке — звук на свободную аудиодорожку в место курсора, картинка — на свободную верхнюю видеодорожку.
  Перетаскивание — на дорожку под мышью. У звука на плитке — кнопка ▶ (прослушать).
- Файл добавляется в «Ваши медиа» как обычный (путь — внутри `plugins/<id>/`); проект ссылается на него, поэтому
  после удаления плагина клипы станут «файл не найден» — до повторной установки.
- `minAppVersion` (необязательно, для любых плагинов) — самая старая версия FF Montage, с которой плагин работает;
  старая программа откажется его ставить с понятной ошибкой. Программы до 0.6.1 поле не знают и `library` не покажут.

## Пресет экспорта, пресет клавиш, действие, панель

```json
"exportPresets": [ { "id": "shorts", "name": "Shorts 1080×1920", "width": 1080, "height": 1920, "fps": 30, "codec": "h264", "quality": "high" } ],
"keymaps": [ { "id": "my", "name": "Мои клавиши", "keys": { "clip.split": ["KeyC"], "tool.blade": ["KeyX"] } } ],
"actions": [ { "id": "show", "title": "Статистика проекта", "keys": ["Ctrl+Shift+KeyI"] } ],
"panels":  [ { "id": "stats", "title": "Статистика", "entry": "panel.html" } ]
```
У пресета экспорта `codec` — `h264`, `hevc` или `av1` (программа сама выберет кодировщик: видеокарта или процессор),
`quality` — `high`, `medium` или `compact`; размеры чётные, от 16 до 8192, `fps` — от 1 до 240.

Клавиши записываются по `KeyboardEvent.code` (`Ctrl+Shift+KeyI`, `Alt+Digit1`) — так они работают в любой
раскладке. Действия видны в «Настройки → Горячие клавиши» (категория «Плагины»), нажатие приходит в `entry`
событием `action`. Панель — страница плагина во вкладке правой панели; SDK в неё подключается сам.

## window.ffm (SDK)

SDK программа вставляет в каждую страницу плагина сама. Все методы возвращают Promise.

```js
ffm.pluginId, ffm.lang ('ru' | 'en'), ffm.apiVersion        // 1
ffm.ready()                                                 // логика/панель готова
ffm.on('action', ({ id }) => {})                            // нажато действие плагина
ffm.project.get()                                           // снимок проекта (JSON)
ffm.project.subscribe((project) => {})                      // изменения проекта
ffm.commands.list() / ffm.commands.execute('clip.split')    // действия программы (как горячие клавиши)
ffm.tools.call('update_clip', { clip_id, volume: 0.5 })     // инструменты ИИ-ассистента (кроме файловых и экспорта)
ffm.register.effect(desc) / .transition / .audioEffect / .exportPreset / .textStyle / .keymap
ffm.register.action({ id, title, keys }, handler)
ffm.ui.notify('Готово', 'success')                          // 'info' | 'success' | 'error'
ffm.storage.get() / ffm.storage.set({ … })
ffm.net.fetch('https://api.example.com/x', { method: 'GET', headers: {} })   // → { status, headers, body }
```

Модель проекта (`project.get()`) — та же, что в файле `.ffproj`: `media`, `videoClips`, `audioTracks`,
`overlayClips`, `episodes`, … В 0.4 она переходит на версию 3 (несколько видеодорожек) — API v1 будет отдавать
и старые поля, пока `apiVersion 1` поддерживается.

## Отладка

- Ошибки плагина пишутся в журнал окна (`<кэш>/app/logs/renderer.log`, ☰ → Настройки → О программе → «Папка журналов»).
- После правки файлов плагина установите папку заново (или выключите и включите плагин).
- Своё выражение FFmpeg удобнее сначала проверить в консоли:
  `ffmpeg -i in.mp4 -vf "vignette=angle=0.5" out.mp4`.
